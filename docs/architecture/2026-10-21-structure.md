# 骑遇目录与模块重构

用户已选择实施结构优化方案。本次为架构重构，目标是路线资料有唯一归属、浏览器和离线工具共用入口、功能模块边界明确，保持37方案、20主线、研究证据与现有交互。

## 决策

- 采用浏览器原生 ES Modules，保留无框架、无运行时依赖的静态部署；本次无需构建器。
- 正式路线按地区收拢到 src/data/routes；待核查资料归 src/data/candidates。历史更新脚本的最终结果合并为当前事实，不再运行覆盖链。
- src/data/index.js 是页面、测试和生成器共同的数据入口；地图几何和道路核验数据在 src/data/generated，地图算法在 features/map。
- src/features 按路线、筛选、收藏、照片、研究、地图拆分；共享导航、坐标、DOM与提示归 shared；纯业务判断归 domain。
- 静态图片与导出地图放 assets。因为不引入构建器，采用可直接HTTP访问的 assets，而不是依赖构建器映射的 public。相对路径兼容GitHub Pages项目子路径。
- 生成器更新生成数据，不再创建根目录补丁。research 保持证据及快照归属，历史文档保留时间语义。
- 视觉和交互不重设计；DESIGN.md与UX-CONTRACT.md记录当前公共所有者及维护边界。

## 验收

迁移前后数据语义一致（只允许本地资源路径迁移）；现有40项数据检查通过；新增检查覆盖模块边界、无浏览器全局依赖与生成器共用入口；桌面和手机浏览器覆盖37方案、筛选、收藏、照片、导航与下载；项目子路径无资源404；离线地图导出与网页共用渲染器。
