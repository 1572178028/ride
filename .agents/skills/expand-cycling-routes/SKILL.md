# 按区域扩充骑遇骑行路线

## 任务与默认行为

用户只需给出一个区域，例如“安吉”“杭州余杭”“太湖东岸”。完成调研、数据编辑、地图导出和页面验证；不要只交付攻略文字或候选清单。

- 默认沿用项目的自驾带车、免费停车、换自行车骑行模式。以用户指定区域为主，跨界延伸须写明实际行政区域和接驳距离。
- 不设固定新增数量上限。尽可能覆盖不同地理方向、风景和难度，持续寻找有依据且可落地的独立主线。以完整性和证据为门槛，不为数量复制线路、虚构商家或降低免费要求。
- 默认兼顾入门短线、半日休闲和较长探索线；真实地形不适合某一类时不要硬凑。长线、山路写清强度及补给缺口。
- 区域可明确定位就开始工作。只有同名地无法判断或缺少必需项目权限时才提问；距离、难度、店铺数量等可选偏好用合理默认值继续。
- 本 skill 本身不构成推送或发布授权。遵循当前会话已有授权：已授权则完成正常提交、推送和上线核查；仅要求本地修改则交付本地结果。不得强推或覆盖无关用户改动。
- 不自动联系商家、运营方或其他人；只使用已获授权的对外沟通能力。没有电话或实地核验，就明确写没有。

开始执行时，用一句中文说明正在使用本 skill，以及所调研区域。

## 分支、版本、合并与 Release（用户约定）

- 每次扩展先检查工作区与 `main` 状态，从 `main` 新建 `codex/<区域>-v<目标版本>` 分支；所有相关修改在分支完成，不覆盖无关用户改动。
- 版本从 `V 1.0.0` 开始，以根目录 `version.json` 为唯一版本数据源，`CHANGELOG.md` 记录历史。
- 每新增一条独立正式主线，末位加1；每新增一个此前未覆盖的城市，中间位加1；每新增一个此前未覆盖的省份，第一位加1。同批分别累计增量，不自动清零低位。例如已有城市新增一线为1.0.1；新增城市及一线为1.1.1；新增省份、城市及一线为2.1.1。
- 长短变体、补图、修正和研究候选不算新增独立路线；完成正式收录及验证后才增加路线版本。未完成的目标版本不得标成已发布。
- 城市按实际地级行政区、省份按省级行政区去重；区县、海宁等县级市和页面筛选分组不单独计为新增城市。
- 更新版本及变更日志，记录基线、正式路线/城市/省份增量、关键来源、验证结果和剩余限制。完成相关目录测试、地图资源、桌面和手机交互验证后，提交开发分支，再合并到 `main`。必要检查失败或正式收录条件未满足则保留开发分支，不声称完成路线或合并。
- 新增线路完成后必须记录 Release：合并后的提交创建 `vX.Y.Z` 标签，推送 `main`、开发分支及标签，并创建对应 GitHub Release（标题 `V X.Y.Z`），正文包含新增线路、城市/省份、主要变化、关键来源、验证结果和未完成的限制。遵循会话授权；本次用户已要求完成后记录 Release，后续任务仍按各自授权执行。
- 仓库已有 `.github/workflows/release.yml`，用户已明确授权其 `contents:write` 权限。版本与Release正文准备好后，先推送版本标签，再推送main触发发布；任务校验标签版本、main祖先关系及目录检查，并从标签读取正文。实际核对Actions与Release结果，已有Release不覆盖。
- 禁止强推或覆盖无关改动。本地提交、合并、标签、远程推送、GitHub Release 和线上核查逐项报告实际状态；网络/权限失败时保存本地 Release 正文，不把文件冒充远程已发布 Release，不对同一版本重复发布。

## 六项交付门槛

### 1. 合法且覆盖完整行程的免费停车

若用户已明确授权采用具名公众车场并将费用/取车时间留待入场确认，按该授权执行，不重复索要确认。将其归入 `feeType: unknown`，显著写“参考免费，费用及取车时间须入场确认”，不显示¥0或纳入免费筛选；保留来源、日期、入口定位精度、接驳及条件缺口。2026-10-20用户已明确允许浦阳江临浦老街车场采用此方式；这不证明全天开放、当前施工恢复，也不自动放宽其他线路的停车条件。


这是正式收录的前置条件，先找停车依据，再围绕可用停车点规划路线。

- 可使用停车场、合法公共泊位、明确对外开放的单位共享车位等，不要求必须是传统停车场。
- 必须有明确的免费依据和可定位的具体停车点。“附近有空地”“没有收费杆”“景区免门票”“网友说可以停”均不构成依据。
- 排除消费抵扣、餐饮或住宿权益、会员专享、短时免停、节庆临时政策，以及无合法停车依据的路肩、厂门和海塘空地。
- 定时免费可以使用，但免费窗口必须覆盖入场、卸装车、全部骑行、探店休息和取车；把限定条件显著展示。夜间免费不能包装成白天免费。
- 起终点优先距停车点合法可通行接驳约500米内。更远须说明实际道路距离、时间和推行要求；地图直线距离不能冒充已确认的接驳。默认环线或原路往返，点到点须有明确返回取车安排。
- 优先读取政府、景区或停车运营方的现行公告，其次可信媒体的实地/电话调查。记录具体停车名称、地址、免费原文摘录、适用人群、开放/取车窗口、是否需预约、发布日期、读取日期和来源URL。
- 读取原文，不能仅凭搜索摘要、转载标题、其他AI回答或无法访问的网页写“已核实”。同一篇报道的转载不算独立佐证。
- 优先最近12个月的明确资料；较旧政策需寻找现行佐证或仍有效的官方公示。日期不明、免费范围不清或有冲突且未解决时，放入待核查区。现有千岛湖无日期记录不作为放宽新增收录的先例。
- 读取公开声明不等于确认到访当天免费。准确展示证据强度；遇收费或开放条件变化时该方案不成立。不能承诺“保证永久免费”。

### 2. 准确说明是否有专用骑行道

每条方案都给出明确结论及覆盖路段，区分自行车专用道、非机动车道、步骑共用绿道、普通道路混行与未确认。

- OSM `highway=cycleway` 或 `bicycle=designated` 不自动证明法律意义的自行车独享。
- `dedicated=true` 仅用于有可靠专用属性依据的路段，并说明局部/全程；`isolated` 指实际有与机动车分隔的路段，不代表排除行人。
- 绿线只叠加主线实际经过的已识别骑行道路段；不能统计片区内未经过的绿道。路线文字、筛选字段和地图须一致。
- 核查禁骑步道、景区限行、单向行驶、快速路、防汛/施工等约束。缺少自行车准入证据的步道不能当作骑行捷径。

### 3. 有依据的沿途餐厅、咖啡和歇脚点

- 每条主线尽量找到餐厅、咖啡和公共休息选择；可以复用同一停车点附近的真实店铺，不按路线重复计店数。
- 使用完整分店名，核对所在城市、地址、公开POI/来源和与路线关系。说明值得停留的具体理由，不能编造实吃体验、评分、价格、营业时间或实时营业状态。
- 区分沿线、起终点周边、需绕行；核实有无合法出口。明显远离路线的店铺不能标成沿途，探店绕行是否计入里程要说明。
- 精确入口未确认时标“片区参考”，导航按完整名称和城市检索；不要捏造POI ID或把地图中心当店门。
- 分开说明公共空间和已证实的厕所、饮水、座椅、修车设施；普通歇脚建议不能冒充设施核验。
- 努力补齐餐厅和咖啡；找不到可靠选项就显示“暂无已核实咖啡店”等缺口及自备补给建议，不能为凑齐字段编造。
- 夜骑、山区等方案须核对补给开放窗口；未知时不能依赖商家开门作为完成路线的必要条件。

### 4. 清晰且基于真实道路的地图

- 获取允许使用的公开道路几何，例如OpenStreetMap/Overpass；保存可重建的快照、来源、读取日期和道路属性。保留OSM署名与ODbL说明。
- 路线由连通且允许骑行的道路节点构成，遵循方向与通行限制，不用途经点间的直线代替道路。不把公开路网规划说成实骑轨迹。
- 沿道路累计距离。原路往返计双程；单向路不能简单反转回程。记录去回、停车接驳和探店绕行的里程口径。
- 地图必须展示完整线路、停车P、道路起点S、途经点与地点名称/编号。停车和道路起点不同须分别标注。
- 保持项目视觉语义：橙色主线、绿色实际骑行道路段、深蓝停车、紫色咖啡C、红色餐厅F、蓝色休息R。字母、编号和图例同时区分类型。
- 调整范围、标签避让和拥挤标记引线，检查水域岸线，避免路线被裁切或标签挡住重点。
- 同步网页地图、所有新方案SVG缩略图和可下载PNG；研究图单独输出，不混入正式统计。

### 5. 百度/高德可打开的起点导航

- 提供停车点驾车导航及道路骑行起点导航，沿用项目对高德和百度的支持。地图起点、文字起点和导航目的地必须一致。
- WGS84用于地图；大陆导航按现有转换器生成GCJ-02，并显式使用相应坐标参数。不能混用坐标系或颠倒经纬度。
- 精确道路起点应有坐标导航；近似停车入口采用完整场所名称导航/检索并标明不确定范围。地点搜索不等于已确认入口。
- URL用结构化参数编码，检查中文、城市、坐标及模式，不能出现 `undefined`、`NaN`。手机App调起无法在当前环境验证时如实说明，不能把链接存在说成真机验证。

### 6. 对应路段的道路实拍

- 按 **小红书 → 抖音 → bilibili → 谷歌搜索** 的顺序逐平台查图。优先站内搜索进入原帖；旧链接失败或单篇验证不代表全站不可访问。前一平台找到足量合格图可停止，否则依次继续补缺。记录实际搜索词、原帖、收录/排除理由及访问障碍，不将未查平台写成已查。
- 每个路线方案尽量配 **3张** 清晰、不同视角或路段的道路照片。长短版仅在确实共线路段复用；不足3张明确待补，不以重复帧或近似地点凑数。
- 主体必须可见骑行道路、路面、标线、坡道/弯道或慢行道结构，通过原帖正文、作者说明、地标或可靠坐标核对方案归属。湖景、建筑、广场、茶田和不在本线的道路不能充作实拍；精确段未确认的片区道路参考不计入3张目标。
- 先通过原帖图片下载保存可获得的最高分辨率文件，并检查下载内容与目标图一致、记录真实像素尺寸。下载失败才截图：先点击图片放大/查看原图；视频先选择最高可用清晰度并放大播放器，等加载清晰且控件消失后截取。不能把缩略图插值放大或AI重绘冒充高清实拍。截图时**仅截图片区域**，不含作者栏、正文、评论、互动按钮、浏览器界面或播放按钮。视频可取可定位的清晰道路帧，记录时间点，保留原图水印，不将相邻近似帧算作不同照片。
- 作者、原帖URL、发布/拍摄日期（未知如实注明）、截取日期、对应路段及版权状态放图注和来源登记。不把非开放许可图标为CC；截取日期不等于拍摄日期。
- 遇滑块或登录验证保留页面，请用户协助完成，不绕过验证；继续独立工作，不用无关景观图替代。
- 接入后逐张目视原图及网页缩略/放大图，核对纯图片、道路主体、正确归属、图注与手机加载；分别统计合格图数与待补数。

## 执行流程

1. **了解现状**：定位包含 `catalog.js`、`app.js`、`map-renderer.js` 的仓库；读取AGENTS.md、README、数据说明及当前Git状态。详细接入要求见 [项目接入说明](references/project-integration.md)。当前技能目录在仓库的 `.agents/skills/expand-cycling-routes/` 下，不依赖固定绝对路径。
2. **建立候选与证据记录**：识别区域的湖岸、江滨、绿道、乡村、山路等不同方向；并行搜索独立资料（不需要启动子代理）。记录研究过的方向及未收录原因，优先对免费停车和通行条件作筛选。
3. **广泛调研并补缺**：围绕合格停车点设计独立主线，补充餐厅、咖啡和休息点，按上述平台顺序补道路实拍，再做一轮相邻方向及资料缺口搜索。持续到主要可骑方向已检查，新增搜索只出现重复或不合格候选；不因达到预设条数提前结束。
4. **生成道路方案**：获得道路快照，构图生成可通行路径并计算里程、骑行道实际覆盖。不能连通就换合法道路或放入待核查，不能画直线补洞。
5. **接入项目**：补充数据、地图、片区筛选、跨城导航、覆盖文案、去重统计和来源说明。长短版共用 `familyId`，相同地点共用稳定标识。每个字段的核对日期只反映真正重新读取过的资料。
6. **待核查单独管理**：保存免费停车、通行或几何证据不足的方向及缺失项。研究图不标免费P、不显示¥0、不生成误导性免费停车导航、不计入正式路线数。
7. **验证**：运行项目相关检查，重新生成SVG/PNG；桌面和手机查看线路、文字、颜色、标签、筛选、地点定位、地图下载及两家导航链接。具体命令与已知硬编码见接入说明。
8. **交付**：任务结束关闭本次检索的后台浏览器标签页；用户仍在处理验证时保留交接页。概括新增主线、方案、实际区域、去重停车和补给数量；给出关键来源和待核查方向。说明已经完成的核验、剩余缺口，以及本地/提交/推送/上线的实际状态。若受网络阻碍，完成可完成的部分，明确哪些数据没有取得，不虚称已完成。

## 完成标准

正式新增的每条方案均有可追溯的合法免费停车依据和完整免费窗口、骑行道结论、真实道路几何、清晰地图及一致的起点导航；餐饮咖啡尽力补齐且缺口如实展示。项目可运行、统计不重复、检查通过或未通过原因已明确。用户要求的是项目补充，不能以一份建议清单代替代码和资源更新。
