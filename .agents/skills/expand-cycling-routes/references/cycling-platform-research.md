# 骑行APP公开路书检索与去重

扩展一个区域时读取本参考。骑行平台用于发现实际骑行方向；停车、准入、几何和正式接入仍按 SKILL.md 的门槛执行。

## 查什么、从哪里查

先从 `src/data/index.js` 列出本区域已有正式方案与研究方向，读取其具体道路、范围、`familyId`和`browseGroup`，再建立“市级 → 区县 → 湖泊/古镇/河流/公路”的检索矩阵。地级市搜索偏向百公里活动时，继续检索县区与地标；同名地核对起终点和地图，特别注意平湖、南湖等异地同名。

- **行者**：访问官网“路书”，进入实际公开站内搜索。当前入口为 `https://www.imxingzhe.com/routes/nearby`，站内检索结果为 `/routes/search?keyword=<编码词>`，详情为 `/routes/<真实ID>`；以当时可见UI为准。搜索引擎 `site:imxingzhe.com/routes/` 只作补充，不代替站内检索。先等结果实际显示，再记录；只看到空壳不写零结果。对有用方向打开原详情，核对活动类型、日期、距离、地图和途经地。需要时加载下一批或切排序；记录实际查看范围，不把默认“更新时间”排序说成热门榜。
  详情异步加载时，临时出现的0km、空标题或缺失作者不作为最终读数；等待有效内容再核对，仍未加载则记录“详情未取得”，结果卡与详情证据分列。
- **Strava**：访问公开 Maps，定位目标区域并选骑行类型，检查实际可见的路线或路段入口。记录地图范围及可用功能。路段是局部计时段，热图是汇总使用线索，都不能直接当作完整路线、骑行许可或热门排名。遇登录/订阅限制，明确哪个功能受限，继续使用可读公开路书及其他平台；不创建付费订阅、不绕过登录或访问控制，不把受限写成当地没有线路。
- **补充平台**：按实际缺口使用捷安特骑游地图、黑鸟、骑记、俱乐部公开骑游记录等。记录实际查看了什么；没有打开的平台不能列为已检索。不能仅凭平台名或活动标题声称“热门”。

## 必填的研究记录

每轮检索保存到 `research/<区域>-cycling-<日期>.md` 或等价结构化文件：

| 记录层级 | 必填内容 |
| --- | --- |
| 检索批次 | 平台、公开入口URL、查询词/地图范围、读取日期、排序、实际页数/加载批次、可见结果与访问障碍 |
| 路书证据 | 真实ID和原URL、标题、作者（公开可见时）、运动类型、原发布日期（未知注明）、平台距离/爬升及口径；哪些来自结果卡、哪些已打开详情 |
| 范围与去重 | 起终点、可辨识途经道路、所属行政区域、对应已有familyId、共线与新增段、独立主线/变体/研究方向的理由 |
| 可落地方案 | 合格停车点、拟采用道路、实际求解里程、是否取得原GPX、与原路书差异、仍缺的准入/方向/连接证据 |
| 处置 | 正式接入ID、并入已有方案、待核查或排除；未完成的检索与下一缺口 |

标题不同、公里数不同、起点不同不自动产生新主线；以主体道路和地理方向判定。长短变体共用familyId，同一区域可用browseGroup集中入口而不抹掉独立主线。跨县不新增地级市，跨省长活动需明确实际区域；不要因为长就直接丢弃，也不能为了新增数量随意切成多条。

## 从路书线索到真实道路

公开详情能定位方向但没有GPX时，可以据道路资料和允许使用的OSM快照独立规划，重新计算里程。页面写清“公开道路独立规划，非原轨迹复刻”，平台距离与本项目里程分列；原路书的爬升、全程距离和实骑身份不能移植给新方案。地图小图、直线规划、轨迹曾经通过均不证明现行合法准入。

优先检查完整环线或合法往返及返回取车安排；不以无标准入的步道补洞。免费停车、道路准入或连通证据仍不足时进入研究区。原完整路线未解决但独立道路方案成立时，在详情保留原线延伸的缺口，避免两个入口重复占据正式列表。接入后继续完成地图、餐咖、图片核对与百度全程/去返程和关键点备用，见[项目接入](project-integration.md)及[完整路程](full-route-navigation.md)。

## 覆盖检查与停止条件

以区域主要地理方向和县区覆盖矩阵检查遗漏，再对新增地标复搜一轮。新增结果只有已覆盖道路、异地同名、准入/停车不合格或已记录的同一缺口时，可结束本轮；写明未查完的平台、结果页和受限功能。没有热度数据只称“公开路书线索”，没有读到完整轨迹只称“方向”，不声称查遍所有骑行APP。

“结束本轮检索”“主要方向已检查”“正式方案已接入”分别报告；受限功能是本轮边界，不能据此声称该平台或区域已查全。
