# 新路线的百度完整路程查看

新增正式方案除停车/道路起点定位外，必须能从详情打开完整骑行路程。研究候选继续留研究区，不伪装为正式导航方案。当前用户优先iPhone Safari→百度App，安卓不是默认新增兼容任务。

## 接入契约

- 数据入口：src/data/index.js；几何为MAP_DATA.paths[id]，必要的方向调整为NAVIGATION_GEOMETRY[id]。新增方案经统一入口载入后，src/features/routes/full-route.js自动呈现，不新增按路线ID散落的HTML。
- 业务模型：src/domain/route-navigation.js组织完整路程；route-waypoints.js按实际道路长度与弯道选择已有道路节点。道路WGS84进入src/shared/navigation.js后转GCJ-02。
- iOS原生链接：baidumap://map/direction，mode=riding、coord_type=gcj02、正确城市与来源；起终点纬度在前，viaPoints为一次编码的JSON。直接用户点击调起，无target=_blank、定时重定向、用户定位收集或AK依赖。不要把返回JSON的Web算路服务当作可打开路线的链接。
- 现有高德/百度停车与起点目的地按钮仍保留。不要向旧网页direction传riding，也不要用“我的位置”做普通地名搜索。

## 路程与拆分

- **闭合环线/双环线/闭合道路方案**：主区域只显示完整环线。起终点相同不能用来判断折返，因为环线也回到起点。
- **完整往返**：全程加独立去程和返程。stops中明确命名折返点；末条常是“返回起点”，不能一律取末条或按长度对半切。
- **多个折返点**：按完整游览顺序确定明确拆分位置（当前实现取最后明确折返点），去程可能含前面支线折返；说明起终地点及单程里程，完整方案不得漏支线。
- **历史原路往返只存去程**：只有核对过可逆的道路才展开双程。存在单行接驳或回程道路不同，独立生成遵循方向和已知转向限制的完整参考路径；原几何/原里程是否改动按任务范围决定，差异须说明。生成器合并NAVIGATION_GEOMETRY，不能手写连接线。
- 新路线优先保存完整道路路径（含合法回程）；shape、stops和路径口径必须一致。已有整段闭合往返不能再次翻倍。

## 选点与备用

- 约1.5km/途经点是当前数量密度预算，不是每段绝对上限；较长路线按内部URL预算限量（目前最多15途经点，非百度容量承诺）。优先保留起终点、折返点、关键转弯、道路接驳及去返程重复经过的节点。
- 只取实际道路几何节点，不直线插值到河面/隔离区域。近似stops吸附到路径上时，名称只表示附近位置，不冒充精确入口。
- 每条方案提供“路线异常或无法打开？”折叠帮助与关键点备用全程。关键点数依据路线确定，保留折返点/重要转弯，不能为了固定5点删掉必要节点；环线备用也要保留足够点约束环向，不能仅传同坐标起终点。检查主/备用链接及点数，不能用完全相同的链接冒充降点备用；短方案必要时给主线路补选真实道路节点，备用保留关键点。
- 原路返回的同坐标应按行进次序保留，不能全局去重。返程切取实际回程路径，单程里程从零计。
- 文案写百度按点重新规划、公里数以百度结果为准，不承诺精确导入轨迹。只有本路线和当前点数确有手机证据，才能写“已测”；浦阳江5/11点的用户反馈不外推到新路线。

## 交付与验证

1. 在来源记录中保留路径/单行方向依据、折返点、全程与单程口径、主/备用点数、参考路径调整及未实测范围。
2. npm test：覆盖全程闭合、单程方向和折返点、顺序/重复点、点数预算、备用不坍缩且严格少于主方案、合法道路方向与坐标编码；不得用“非空链接”替代这些验证。
3. npm run test:browser及RIDE_TEST_BASE_PATH=/ride npm run test:browser：桌面/手机切换新方案，查看完整路线、去返程分支/环线单入口、展开备用与点清单、正确城市、资源无404和无溢出。
4. 桌面移动视口检查的是网页和请求参数，不是iPhone百度App内部算路。条件允许时请用户手机核对点数、方向、地图及公里数，记录实际证据，不阻断已授权且可完成的工程接入。
5. 遵循会话已有提交/推送授权，更新相应Release说明并确认部署；不得移动旧标签或把本地记录称为远程已发布。
